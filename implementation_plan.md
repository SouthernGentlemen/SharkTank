# Implementation plan

## Open tasks

MVP target for every task below: SharkTank is the game at `/play/`, a short server-rendered overview at `/`, one live operations page at `/evidence/`, and the authenticated operator console at `/admin/`, with only the JSON that the game, those pages and operators call. ISO/IEC 27001 and 42001 assurance lives at demo.wizardgang.ai/assurance. Keep billing measurement and the spend hard stop, Durable Object class names and migration `v1`, stored Lobby and Room state, R2 copies, deterministic replay, strict CSP, no-JavaScript completeness of Worker pages, and the protected release and deployment path. Each task updates the tests, acceptance scripts and documents its change invalidates. Retired routes return the standard 404 unless the owner decides otherwise. Only ST-108 may create a tag, GitHub Release or production deployment.

Shared validation for every task: pinned `npm ci`, focused tests for the touched modules and scripts, canonical `npm run check`, `npm run audit:dependencies`, committed-range whitespace, exact-head required CI, post-merge CI, history and completed-branch cleanup.

- Dependency: ST-102 has merged.
- Why: ISO/IEC 27001 and 42001 assurance is now published at demo.wizardgang.ai/assurance. The demo's register assesses the architecture demo and does not mention SharkTank, so this retires SharkTank's claims rather than moving them.
- Scope: Remove `src/worker/conformance.ts`, `src/worker/governance.ts`, the ISO and controls generators and their CSS, `renderControlsDocument`, `renderPolicyNotFoundDocument`, `/controls(/)`, `/policies.json`, `/audit/manifest.json`, and the `/iso-27001`, `/iso-42001`, `/audit`, `/policies` and `/policies/:id` redirects. Rewrite the overview for the MVP from one Lobby status read: lead with Play, say what SharkTank is, keep a live snapshot (tank availability from recorded incidents, spend against the hard stop, current release, receipt-chain verdict), link Evidence and GitHub, and add one outbound link to the WizardGang portfolio assurance at demo.wizardgang.ai/assurance. Remove the ISO chips, standard cards, governance narrative and governance or ISO wording from titles, meta descriptions and the `/play/` document. Primary navigation becomes Overview, Evidence and Play; the footer drops the register and policy JSON links and the case-study note; evidence and admin copy stop linking the register. Rewrite `scripts/check-evidence.mjs` in place from an ISO-manifest walk into a read-only check of the public MVP surface (canonical pages, `/status.json`, `/spend.json`, `/version.json`, the unauthenticated `/admin/` 401 and retired-route 404s) that never authenticates or opens a room socket, so the `npm run check:evidence` step in `.github/workflows/deploy.yml` and its `scripts/release-workflow.mjs` contract stay unchanged. Delete `tests/conformance.test.ts`; update `check-public-ia`, the accessibility and presentation tests and the PR template. Delete `docs/AI-APPLICABILITY.md` and remove ISO readiness statements from README, `docs/ARCHITECTURE.md` and `docs/SECURITY-MODEL.md`.
- Non-goals: Keep the operations the claims pointed at (incidents, receipt chain, backups and restore drills, spend gate, logs and admin) and billing unchanged. Add no SharkTank claims to the demo. Do not edit the deploy workflow. No release.
- Owner decision: `/controls/` returns 404 by default; the alternative is a one-hop 301 to demo.wizardgang.ai/assurance.
- Acceptance: No Worker-rendered page asserts ISO/IEC 27001 or 42001 implementation, Annex A applicability or certification readiness; `/controls/`, `/policies.json`, `/audit/manifest.json` and the former ISO redirects return 404; the sitemap lists `/`, `/evidence/` and `/play/`; internal links resolve without redirect hops; the rewritten `check:evidence` passes against the local Worker.
